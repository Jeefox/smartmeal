# SmartMeal

Учебный планировщик питания и покупок: Java 21, Spring Boot 4.1.1, PostgreSQL и React + TypeScript + Vite.

## Что работает

- Регистрация и вход: хеширование паролей, серверная сессия и CSRF-защита.
- Личный профиль, анкета и предварительная оценка калорий; подтверждение цели отдельно от расчёта.
- Продукты и категории; поиск и пагинация; создание и чтение рецептов с КБЖУ.
- Меню дня: дробные порции, неизменяемые снимки рецептов, итоговое КБЖУ, редактирование черновика и подтверждение.
- Список покупок за 1–31 день: агрегация ингредиентов из снимков меню текущего пользователя.
- Сети и магазины, семь выбранных точек Тулы.
- Товары в упаковках, ручное добавление наблюдений цен и получение последнего наблюдения по дате.
- Flyway V1–V8, unit-тесты, интеграционные тесты PostgreSQL и проверки API с Spring Security.

Расчёты питания приблизительные, коэффициенты являются начальной моделью приложения. Предварительная рекомендация не заменяет сохранённую цель без подтверждения пользователя.
Автоматический подбор меню, загрузка чеков, интеграции цен магазинов и расчёт закупки с бюджетом ещё не реализованы. Демонстрационные цены интерфейса не являются реальными предложениями магазинов.

## Запуск бэкенда

Нужны JDK 21, Docker и Docker Compose.

Скопируйте `.env.example` в `.env` и задайте собственный `POSTGRES_PASSWORD`.
Spring Boot и Compose читают `.env` из корня проекта; в IDE выберите этот рабочий каталог.

```bash
docker compose up -d --wait
bash mvnw spring-boot:run
```

Бэкенд: http://localhost:8080. PostgreSQL: localhost:5433, база и пользователь `smartmeal`.
Пароль хранится только в локальном `.env`. Изменение этого файла не меняет пароль существующей БД.
Схемой управляет Flyway; применённые миграции не редактируются.

API требует входа. Для регистрации и входа сначала получите `GET /api/auth/csrf`, сохраните cookie и передайте токен в заголовке, имя которого указано в ответе.
Регистрация: `POST /api/auth/register` с JSON `{email, password}`. Вход: `POST /api/auth/login` с `application/x-www-form-urlencoded`, поля `email` и `password`.
После входа получите CSRF-токен заново. Текущий выход использует стандартный `POST /logout` с CSRF.

## Запуск фронтенда

Нужны Node.js >=22.12.0 и npm.

```bash
cd frontend
npm ci
npm run dev
```

Клиент: http://127.0.0.1:4173. Vite проксирует API в бэкенд на порту 8080.
В интерфейсе явно разделены деморежим и режим API. Демо хранится отдельно и не подменяет ошибки реального сервера.
Новый React-клиент находится в `frontend/`; `src/main/resources/static/` содержит прежний прототип, который не является production-сборкой React.

Подробности: [frontend/README.md](frontend/README.md), [документация интерфейса](docs/FRONTEND.md).

## Проверки

Все тесты бэкенда, включая интеграционные, требуют запущенную локальную PostgreSQL:

```bash
bash mvnw test
```

Только unit-тесты калькуляторов, без БД:

```bash
bash mvnw '-Dtest=*CalculatorTest' test
```

Из `frontend/`:

```bash
npm test
npm run build
npm run test:e2e
```

Для браузерных тестов нужен Chromium Playwright (`npx playwright install chromium`). Они используют изолированные ответы API; интеграционные Java-тесты обращаются к PostgreSQL и откатывают свои записи.
