# SmartMeal — React frontend

Новый клиент расположен в `frontend/`, заменяя целевую архитектуру старого HTML-прототипа. Бэкенд в корне не переносился и не изменялся фронтенд-задачей. Старые файлы `src/main/resources/static/` сохранены для обратного перехода.

## Запуск

```bash
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:4173/ . `/api` проксируется на Spring Boot, порт 8080. На порту 8080 остаётся старый прототип. Подробные команды, структура, режимы и ограничения — в `frontend/README.md`.

## Экранная карта

Сегодня `/`, неделя `/week`, каталог `/recipes`, карточка `/recipes/:id`, создание `/recipes/new`, редактор `/recipes/:id/edit`, продукты `/products`, покупки `/shopping`, магазины и бюджет `/stores`, профиль `/profile`, настройка `/onboarding`, формы входа/регистрации `/login` и `/register`.

Навигация на телефоне: Сегодня / Рецепты / Покупки / Профиль. Дополнительные экраны доступны из бокового меню. Единые токены и компоненты, области основных действий 44px, фокус клавиатуры, reduced-motion.

## Режимы и границы

- Демо явно отмечено на всех экранах. Меню, профиль, покупки и условные цены хранятся только в выделенном demo-хранилище браузера. Это не серверное хранение и не реальная ценовая интеграция.
- В режиме API клиент обращается к продуктам, категориям и рецептам. Никакого локального списка UUID и демоподмены ошибок. Для каталога нужен RecipePageResponse с кратким RecipeSummaryResponse; не полный состав каждого рецепта.
- Нормализуются оба имени времени: `preparationTime` текущего краткого DTO и `preparationTimeMin` детального. Расширенные фильтры ожидают backend-контракт.
- Профиль, auth/CSRF, ручное серверное меню, автоподбор, магазины, котировки и покупки ждут соответствующих модулей. Подготовленные формы не имитируют вход и не отправляют пароли.
- Ручное меню, порции, закрепления, упаковки, бюджетные состояния, отметки и замены демонстрируются интерактивно; бизнес-расчёты production остаются на Java.
- Manifest/иконки/service worker добавлены; offline-чтение демосписка проверено на production-preview после согласия, offline-запись заблокирована. Установка на реальный телефон ещё не проверена.

## Проверки

14 unit-тестов и production build. Через Playwright проверены 11 маршрутов на ширинах 360, 390, 768, 1440 px, ключевые действия и подставные ответы API. Реальная БД и компиляция параллельно редактируемого бэкенда не проверялись.

Скриншоты и визуальные решения: `docs/ui/README.md`. Это первая реализованная версия дизайна по ТЗ, не утверждение о завершении всех этапов релиза. Локальное ТЗ и исследование не коммитились и никуда не публиковались.
