# Быстрое заполнение реальных цен

Реализованный сценарий: выбрать магазин → получить ингредиенты рецептов без обычной цены → ввести несколько наблюдений → сохранить одним запросом. Без внешнего API и без предположительных цен.

## Интерфейс

Покупки → Упаковки и цены → выбрать город и конкретный магазин → **Быстро заполнить цены**.

- Продукты упорядочены по количеству использующих их рецептов, затем по названию и ID.
- По умолчанию скрыты продукты, у которых есть хотя бы одна активная упаковка с неаннулированным обычным наблюдением цены. Возраст цены пока не ограничивается; это наличие сохранённой цены, а не подтверждение её сегодняшней актуальности.
- Единственная известная упаковка выбирается автоматически. Историческая цена не подставляется в поле новой цены, чтобы её случайно не подтвердили как новое наблюдение.
- При отсутствии упаковки предложено покупное название; пользователь уточняет его и фактическую целую массу в граммах. Несколько упаковок требуют выбора.
- Можно пропустить неизвестные цены. Весь заполненный список, включая строки с других страниц, сохраняется одной операцией. На запрос максимум 100 строк.
- Вставка Excel/текста: три столбца `продукт;вес_упаковки_г;цена` или табуляция; десятичная запятая поддерживается. Название однозначно сопоставляется с базовым/покупным названием на текущей странице. При неизвестном, повторном или неоднозначном продукте ничего не применяется. Результат вставки остаётся черновиком до явного сохранения.
- Дата наблюдения общая для запроса; переключатель акции отдельный для строки. Акционные/специальные цены не участвуют в текущей смете по обычным ценам.
- Текущая модель — упаковки с известной массой. Нельзя записывать цену за килограмм весового товара как цену неизвестной упаковки. Весовую и штучную продажу необходимо поддержать отдельно.

## GET /api/stores/{storeId}/price-entry

Параметры: `missingOnly=true`, `q=` (буквальный поиск по названию, до 100 символов), `page=0` (0…1000000), `size=20` (1…100).

Ответ:

```json
{
  "content": [{
    "productId": 7,
    "productName": "Рис сухой",
    "shoppingName": "Рис",
    "recipeCount": 5,
    "offers": [{
      "storeProductId": 90,
      "name": "Рис 900 г",
      "packageWeightG": 900,
      "price": null,
      "observedAt": null
    }]
  }],
  "page": 0,
  "size": 20,
  "totalElements": 1,
  "totalPages": 1
}
```

`offers` содержит только активные упаковки этой точки. Цена — последнее неакционное, неаннулированное наблюдение конкретной упаковки; при отсутствии `null`. Учитываются продукты всех существующих рецептов, а не только текущего меню и не все продукты справочника. Цены/упаковки другого магазина не подставляются.

## POST /api/stores/{storeId}/price-entry

Нужны сессия и CSRF. Пример (идентификаторы условные):

```json
{
  "requestId": "90a1284d-5abc-44a2-88cc-f984d4a16d9c",
  "observedAt": "2026-10-20T09:00:00Z",
  "entries": [
    { "productId": 7, "storeProductId": 90, "price": 79.90, "promotional": false },
    { "productId": 8, "name": "Овсяные хлопья 450 г", "packageWeightG": 450, "price": 59.00, "promotional": false }
  ]
}
```

Для существующей упаковки передаётся `storeProductId`; `name` и `packageWeightG` должны отсутствовать/null. Для новой — название 1…300 непробельных символов и положительная целая масса до 2147483647 г. Дробная масса не округляется и даёт 400. Точное совпадение активного товара магазина по productId, имени и массе переиспользуется. Разные массы не склеиваются. Неактивные товары не восстанавливаются автоматически.

Цена положительная, максимум 10 целых и 2 дробных знака. Дата не в будущем. `promotional` обязателен. Продукт не повторяется внутри запроса. Один запрос может содержать от 1 до 100 строк. Продукт должен существовать, но не обязан уже использоваться в рецепте.

Ответ 201:

```json
{
  "requestId": "90a1284d-5abc-44a2-88cc-f984d4a16d9c",
  "storeId": 11,
  "savedCount": 2,
  "entries": [{
    "productId": 7,
    "storeProductId": 90,
    "priceObservationId": 100,
    "createdStoreProduct": false
  }]
}
```

В реальном ответе `entries` содержит все сохранённые строки; выше показана структура одной строки. Источник цены всегда `MANUAL`, его нельзя назначить из запроса. Старая история остаётся, время загрузки не подменяет `observedAt`. После успеха фронтенд инвалидирует каталог, наблюдения и сметы.

## Повторы и ошибки

V12 добавляет `price_entry_batches` с ключом `(user_id, request_id)`, хешем запроса и исходным ответом. Повтор тем же пользователем с тем же ключом и теми же данными возвращает тот же ответ 201, не создавая новых цен/упаковок. Изменённые данные с прежним ключом дают 409. Это один исходный запрос, включая дату, порядок строк и значения чисел; не редактировать его при повторе.

Запись транзакционная. Ошибка любой строки откатывает весь пакет и создание упаковок. Задания одного пользователя сериализуются блокировкой его строки; создание упаковок в пакетах одной точки сериализуется блокировкой магазина. Существующие SKU блокируются и проверяются на активность и принадлежность. Подтверждённый ответ хранится только в контексте отправившего пользователя.

При сетевом сбое/5xx и ошибке доступа во время повтора фронтенд сохраняет исходное тело и ключ в памяти и, при доступности, sessionStorage, привязанном к пользователю и магазину. Автоматических POST-повторов нет. Редактирование при неопределённом исходе блокируется; доступен явный безопасный повтор. Перезагрузка той же вкладки восстанавливает запрос. Успешный POST не считается неуспешным, если последующий GET обновления сметы упал.

Коды: 400 — неверные данные; 401 — нет сессии; 403 — CSRF/доступ; 404 — неизвестный магазин/продукт/упаковка; 409 — неактивная точка, недоступная/чужая упаковка или конфликт ключа.

## Проверки

Интеграционные проверки включают отсутствие вымышленных цен, сортировку и фильтры, акции/аннулирования, пакетное создание и переиспользование упаковок, одинаковые и конкурентные повторы, другой магазин, полный откат и валидацию массы/денег. Браузерные проверки: ручной ввод, вставка таблицы, потеря ответа и перезагрузка, CSRF при повторе, страницы, конфликт, мобильная ширина и сбой GET после успешной записи.
