# Официальные каталоги сетей

Сборщики работают с публичными витринами Магнита, Глобуса, Перекрёстка и
Пятёрочки. Партнёрский токен не нужен. Используется отдельный профиль Firefox
для каждой сети, а не личный браузер пользователя.

## Запуск

Нужны Node.js, зависимости frontend (`npm ci` в frontend) и Playwright Firefox:

```bash
node frontend/node_modules/playwright/cli.js install firefox
node scripts/collect_catalogues.mjs --headed
```

Сети обходятся **последовательно**, чтобы не запускать четыре браузера одновременно.
По умолчанию выбираются продуктовые разделы: овощи и фрукты, молочные продукты,
мясо и рыба, бакалея, хлеб, консервы, заморозка, орехи. Это не бытовые товары и
не весь ассортимент сети. Фактические выбранные разделы перечислены в снимке.
`--all` включает все обнаруженные разделы, включая непродуктовые.

```bash
node scripts/collect_catalogues.mjs --headed --watch
node scripts/collect_catalogues.mjs --chains=magnit,globus --headed
node scripts/collect_retail.mjs perekrestok --headed
node scripts/collect_retail.mjs pyaterochka --setup --categories=251C51627
```

В `--setup` нужно дождаться каталога, при необходимости вручную пройти проверку,
затем нажать Enter в терминале. Выгрузка продолжается в том же окне.
Обход проверки и автоматическое решение CAPTCHA не выполняются. Доступ через
обычный браузер не гарантирует, что сайт разрешит автоматическую выгрузку.
Перекрёстку и Пятёрочке может требоваться `--headed`; на сервере для него нужен
графический сеанс. Постоянное получение данных без ручных проверок не гарантируется.

Режим `--watch` проверяет сроки каждый час: успешный источник обновляется через
7 дней, неудачный — через сутки. Процесс должен работать постоянно; команда
не устанавливает системную службу. На headless-сервере можно начать без
`--headed`, но при проверке сайт останется недоступен до ручного действия.

## Снимки, возобновление и ошибки

Вывод: `data/runtime/<chain>/` (игнорируется Git).

- `categories/<id>.json` — полностью загруженный отдельный раздел.
- `pages/<id>-<page>.json` — проверенные наблюдения одной страницы (`OBSERVED_PAGE`);
  это **не** подтверждение полной загрузки раздела или всей сети.
- `latest.json` — весь выбранный набор разделов, только после его завершения.
- `status.json` — результат последней попытки.
- `profile-firefox/` — локальная сессия; не публиковать и не копировать в Git.

Завершённые разделы повторно используются в течение 7 дней. `--force` загружает
их заново. У объединённого снимка сохраняется наиболее ранняя дата данных;
чтение файла не делает старые цены свежими. Смена региона/магазина сайта
отменяет повторное использование снимков прежнего контекста.

`--categories=id,id` ограничивает выгрузку конкретными корневыми разделами.
`--max-pages=N` ограничивает количество запросов для диагностики: при достижении
лимита незавершённый набор не публикуется как полный.

При ошибке уже проверенные разделы и предыдущий `latest.json` сохраняются.
Отдельные проверенные страницы тоже сохраняются и могут дать справочные цены,
даже когда весь раздел не докачался. У страницы хранится её фактический контекст
магазина/региона. При HTTP 403/429 источник останавливается; защита не обходится.
У Магнита полнота определяется штатными `hasMore` и `nextOffset`: смещение
не равно номеру страницы × размеру страницы. У Глобуса проверяются номер,
число страниц и количество товаров. При неизменном числе товаров требуется
точное совпадение. Если живой каталог менялся в ходе загрузки, сохраняются
`verification=LIVE_CATALOGUE_CHANGED` и диапазон наблюдавшихся количеств;
итог должен попасть в этот диапазон, а изменение не должно превышать 5%
(минимальный допустимый диапазон — 5 позиций). Это полный обход наблюдавшихся
страниц, а не атомарный снимок ассортимента: товар, переместившийся между
страницами во время обхода, может быть пропущен. Для справочных цен это допустимо;
наличие в магазине по этим данным не обещается. У Перекрёстка — `nextPageExists`.
У Пятёрочки используется наблюдавшийся запрос с limit/offset до короткой
или пустой последней страницы. Повтор страниц без новых товаров завершает
выгрузку ошибкой, а не создаёт бесконечный цикл.

## Какие данные используются

Официальные витрины:

- https://magnit.ru/catalog/ — запрос интерфейса `/webgate/v2/goods/search`.
- https://www.globus.ru/catalog/ — структурированные данные Next.js с пагинацией.
- https://www.perekrestok.ru/cat — структурированное состояние каталога и страницы `?page=N`.
- https://5ka.ru/catalog/ — запросы интерфейса `https://5d.5ka.ru/api/catalog/`.

Регион/магазин по умолчанию сохраняется в `sourceContext`. Это **региональные
справочные цены**, а не обещание цены или наличия в выбранном пользователем
магазине Тулы. Приложение не заставляет пользователя выбирать конкретную точку.

Обычная цена хранится отдельно от текущей акционной и условий акции. Для
Глобуса сохраняются условия карты; для Пятёрочки и Перекрёстка — метаданные
акций. У Магнита не вычисляется непроверенная обычная цена весового товара
по перечёркнутой цене выбранного количества. Цена за 100 г Пятёрочки и цена
выбранного веса Магнита приводятся к цене за 1 кг по явным данным источника.
Неопределённые фасовки и мультиупаковки не превращаются в выдуманную массу.

## Импорт в приложение

`RetailSnapshotImporter` раз в час читает завершённые снимки, разделы и отдельные
проверенные страницы с явно указанной областью `OBSERVED_PAGE`;
первый запуск — через минуту после старта приложения. Отдельного REST-запроса
для импорта не требуется. Настройки:

```properties
smartmeal.prices.retail.snapshot-directory=data/runtime
smartmeal.prices.retail.import-delay-ms=60000
smartmeal.prices.retail.import-interval-ms=3600000
```

Импортируется только обычная цена доступного товара, безопасно сопоставленного
с ингредиентом рецепта. Используется `catalogue_price_references`, а не наблюдение
реальной цены конкретного магазина. Условные цены без известной обычной цены
пропускаются. Срок — 15 дней от первоначальной загрузки. Повторный импорт не
сдвигает дату и не переписывает более свежие данные старыми.
