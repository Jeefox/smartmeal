# Вес ингредиентов и покупок

Количество ингредиента рецепта задаётся в граммах сырой съедобной части до приготовления.
Пищевая ценность продукта относится к 100 г этой части; поправка на очистку не увеличивает калорийность блюда.

Поля Product и ответов `/api/products`:

- `shoppingName` — название для покупок, например «Бананы» вместо «Банан без кожуры».
- `edibleYield` — доля съедобной части купленного продукта: `0 < edibleYield <= 1`, до 6 знаков после запятой.

Вес для покупки = вес ингредиента × порции / порции рецепта / edibleYield.
Расчёт выполняется по каждому вхождению до суммирования; итоговая масса округляется до сотых грамма HALF_UP, как раньше.
Список покупок, оценки стоимости и сравнение магазинов используют покупной вес.
Сухие макароны обычно не требуют поправки на очистку: коэффициент 1.
Коэффициенты для продуктов с отходами задаются явно; система не подставляет оценку за пользователя.

POST продукта без новых полей использует shoppingName=name и edibleYield=1.
PUT без новых полей (или с null) сохраняет прежние настройки покупок; для сброса передайте их явно.
Переданное непустое shoppingName очищается от пробелов по краям; пустое отклоняется с 400.

Новые записи меню сохраняют shoppingName и edibleYield в RecipeIngredientSnapshot.
Изменение справочника продуктов не меняет существующие снимки, включая черновики.
Для старого JSON без новых полей используются productName и edibleYield=1; миграция не переписывает историю.
Следовательно, существующее меню не начнёт учитывать очистку после редактирования продукта:
чтобы применить новые настройки, удалите и заново добавьте блюдо в редактируемое меню.

Группировка и поиск магазинных упаковок остаются по productId, не по названию.
Одинаковые shoppingName с разными productId не объединяются.
Новая миграция V9 копирует текущее имя в shopping_name и задаёт edible_yield=1 для существующих продуктов.
